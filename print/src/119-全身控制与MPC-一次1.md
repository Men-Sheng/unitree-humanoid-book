# 全身控制与 MPC：一次 1 kHz 里要解完的那堆方程

## 23 个未知数，一毫秒解完

上一章讲了一个关节的软硬。现在的问题是：一台 G1 有 23 个（EDU 版 29 个）关节，同时脚踩在地上、手要够到某个位置、躯干不能歪、关节不能超限、地面不能给拉力——**这些要求互相冲突时，谁让步？**

这就是全身控制（Whole-Body Control，WBC）要解的东西。它的输入是一堆任务和约束，输出是 23 个扭矩数，交给第 12 章那条链。

本章不打算教你怎么写 WBC（那是另一本书），只打算给你一件对工程师最有用的东西：**这件事的计算量随自由度怎么涨，以及为什么这条曲线决定了人形机器人的形状。**

## 先看清楚要求有几类

| 类别 | 内容 | 在优化里的身份 |
|---|---|---|
| 动力学等式 | τ = M(q)q̈ + C(q,q̇) + g(q) − JᵀF | 等式约束（不能违反物理） |
| 接触约束 | 脚不穿透地面、不滑动、法向力 ≥ 0 | 不等式约束 |
| 任务 | 重心轨迹、末端位姿、姿态、避免自碰 | 目标函数（可以打折） |
| 执行器限制 | \|τ\| ≤ τ_max、\|q̇\| ≤ ω_max、q 在行程内 | 盒式约束 |
| 摩擦锥 | \|F_切向\| ≤ μ·F_法向 | 二阶锥约束（或它的多面体近似） |

**关键结构**：第一类是“物理不许你违反”，第三类是“你希望尽量满足”。所以这天然是一个**带约束的二次规划（QP）**：在满足前两类与后两类硬约束的前提下，最小化第三类的加权误差平方和。

优先级也可以显式表达（严格分层：先保证不穿透地面，再保证重心，再保证手的精度），这叫任务优先级（task-priority）或分层 QP。

## 计算量：为什么自由度是原罪

设关节数 n。这个 QP 的决策变量通常是 q̈（n 维）加上接触力（每个接触点 3 维，两只脚就是 6 维）。

```text
矩阵规模 ≈ (n + n_c) × (n + n_c)
求解一个稠密 QP 的工作量 ≈ O(m³)，m 是变量维度
```

代具体数：

```text
G1  23 DoF + 6 维接触力 = 29    ⇒ 29³ = 24,389
G1  29 DoF + 6          = 35    ⇒ 35³ = 42,875
H2  31 DoF + 6          = 37    ⇒ 37³ = 50,653
```

（[算]。）

**从 23 个自由度到 31 个，一次求解的工作量涨 2.08 倍。** 而这条曲线是三次方的：如果哪天做一台 60 自由度的人形，(60+6)³ ÷ (23+6)³ = 11.8 倍——注意这是**相对 23 自由度那一档**；相对刚才那台 31 自由度的机器，是 66³ ÷ 37³ = 6.3 倍。基址不同，倍数差一倍，这类“涨几倍”的说法必须带基址。

再看时间预算。第 12 章说过整机低层话题是 500 Hz [厂]，控制层通行量级是 1 kHz [行]：

```text
1 kHz ⇒ 每次求解预算 1 ms
```

1 毫秒解一个 37 维 QP，在嵌入式 x86 上是**可行的但紧张**（商用求解器通常几十到几百微秒），在关节 MCU 上是不可能的。所以真实的架构一定是：

```text
主控（x86 或 Orin）跑 WBC/MPC  →  1 kHz  →  分发 23 个 τ_cmd
关节 MCU 跑级联三环            →  kHz 量级 →  占空比
```

**这条分工不是软件偏好，是 O(m³) 与 1 ms 这两条线交出来的。**

（宇树从未公布整机是否在线跑 WBC 或 MPC，也没公布求解器与频率 [未]。它公开的运控工序是强化学习（第 21 章）。本章给的是“如果显式解，代价是多少”。）

## 模型预测控制：把“下一步”变成“下 N 步”

QP 只决定当前这一瞬间的加速度。MPC 的差别是：**它把未来 N 步的模型一起展开，一次性优化整段轨迹，然后只执行第一步，下一周期重来。**

这带来一个 WBC 给不了的能力：**它能提前准备。**

对第 17 章的捕获点问题，这一点是决定性的。纯反馈的 ZMP 控制器是“已经开始歪了才纠正”；MPC 是“我预见到 200 毫秒后我会歪到那里，现在就把这一脚迈过去”。而**摆动相需要 200 毫秒**——也就是说：

> **任何只看当前时刻的控制器，在物理上来不及决定落脚位置。**

这就是为什么双足走路绕不开某种形式的预测（显式 MPC，或者被训练进 RL 策略里的隐式预测）。

代价是模型规模再乘一个视界：

```text
N 步视界 ⇒ 变量维度 ≈ N × (n + n_c)
N = 20 步、37 维 ⇒ 740 维 QP ⇒ 740³ ≈ 4 亿次运算量级
```

（[算]。）**所以人形的 MPC 视界通常只有几十步、模型通常被简化成线性倒立摆（LIPM）**——不是不想用完整模型，是 1 ms 装不下。

这里有一个非常值得工程师记住的取舍：**MPC 的精度受限于你能塞进实时预算里的那个模型的复杂度。** 于是“用什么样的简化模型”就变成了控制研究的核心问题，而 LIPM（第 17 章那套）之所以活了几十年，就是因为它在“够用”与“算得起”之间的那个点上。

## 真正爆炸的不是维度，是接触模式

上面所有算术都有一个隐藏前提：**你知道脚什么时候着地。**

如果不知道，问题就变成：单脚支撑、双脚支撑、腾空、三点接触、躯干撞地……这些**接触模式**的组合。走 N 步、每步有 3 种模式，就是 3ᴺ 种序列。这是一个组合爆炸，任何“枚举再挑最好”的方法在几十步视界上直接死掉。

工程上三条出路：

**一、预设模式序列。** 你告诉求解器“第 0–200 ms 左脚着地，200–400 ms 双脚，400–600 ms 右脚”。这就是传统步态规划。代价：不预设就不会动，被推一下导致模式变了就崩。

**二、混合整数规划（MIQP）。** 让求解器自己选模式。数学上优雅，计算上是 MIP——**指数复杂度**。实时预算里基本不可能。

**三、不显式处理。** 用自由轨迹（foot placement 由策略决定）或者干脆用强化学习，让网络自己内化“什么时候该踩哪里”。

**第三条是 2016 年之后足式运控赢的那条**，而它赢的原因不是网络更聪明，是**它把一个指数复杂度的问题换成了一个固定规模的前向推理**。一次策略推理的算力只取决于网络大小，与“未来有多少种接触序列”无关。

**这就是第 21 章存在的理由。** 但请注意代价：你换掉了指数爆炸，也换掉了可解释性——出问题时你无法说“是哪一条约束被违反了”。

## 于是可以解释一台人形长什么样

把本章的算术倒过来读，能解释几个看起来是审美选择的东西：

**为什么腰只有 1–3 个自由度？** 每加一个自由度，QP 规模按三次方涨，而腰对“不摔”几乎没有贡献（它在重心正上方，不改变支撑多边形）。G1 基础版腰 1 个、H2 三个、G1+ 是立柱加底盘。**腰部自由度是拿算力换灵活性的，而算力在 1 kHz 那一层最贵。**

**为什么手腕有 3 个自由度但只有 5 N·m？**（第 15 章的 W4010-25。）因为腕不参与平衡，它的力矩需求只由“把手掌摆到某个朝向”决定，而那个需求的量级就是几牛米。省下的重量全砸在腿上了。

**为什么手指是另一套器件？**（第 25 章。）因为手的接触模式数量比脚多一个数量级（每个指节都可能接触），如果把它塞进同一个全身求解里，QP 规模直接爆掉。所以工程上手的控制是**解耦**出来的——它是另一个环，不与平衡抢那 1 毫秒。

## 类比，以及它在哪儿破

类比：WBC 像一个同时管 23 个员工的经理，每个员工有自己的上限（执行器限制），部门之间还有硬性依赖（动力学），而经理每一毫秒要给出 23 条指令。

**这个类比在哪里破**：经理可以给“尽量做好”这种模糊指令，而 QP 必须把所有目标写成**加权平方和**——也就是说，你必须提前决定“手的精度值多少、躯干姿态值多少”。这些权重是控制器的真正设计变量，而它们**没有物理正确答案**。同一个机器人，换一组权重，走路姿态完全不同。

这就是为什么足式控制论文里“任务权重怎么调”通常被含糊带过——它是手艺，而手艺不能证明。

---

**一个可检验的说法**：全身控制的标准形式是带约束的二次规划，其变量维度约为关节数加接触力维度，稠密求解工作量按三次方涨，因此 G1 的 23→29 自由度使单次求解成本涨 1.76 倍、到 H2 的 31 自由度涨 2.08 倍；在 1 kHz 控制周期（1 ms 预算）下，这决定了 WBC 必须跑在主控而非关节 MCU 上；而真正的组合爆炸来自接触模式而非维度，这是显式优化路线让位于强化学习的计算原因。

**证据等级**：QP 结构、O(m³)、LIPM 简化、混合整数的指数复杂度、摩擦锥与接触约束，全部是优化与足式控制的标准内容 [行]；29³/35³/37³ 与 2.08 倍、740³ 是 [算]（**假设稠密求解**，实际用稀疏/迭代法会显著不同，本书给的是量级直觉不是实现预测）；500 Hz 低层话题 [厂]、1 kHz 控制层量级 [行]；G1/H2 的自由度分解 [厂]；腕关节 5 N·m 与腰部配置 [厂]（`unitree_rl_lab` 配置）；**宇树是否在线跑 WBC/MPC、用什么求解器、什么频率，全部未公布** [未]；“腰自由度是拿算力换灵活性”是本书推断 [算][行]。
