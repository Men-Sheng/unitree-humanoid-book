# 倒立摆、ZMP 与捕获点：站稳的判据到底是什么

> 状态：初稿 v1（2026-10-08）。第 2 部第二章。本章要把“稳”从一个形容词变成一个可算的数。

## “它看起来挺稳”不是判据

上一章说双足必须让重心投影持续落在支撑多边形（支撑多边形 = 所有接触点连成的凸包，第 16 章）里。这句话还是几何直觉。工程师会立刻问两个问题：**投影在哪，我怎么算？以及“落在里面”是不是太保守？**

第二个问题尤其关键。因为一个正在往前走的人，他的重心投影**本来就在他支撑脚的前面**——他是在往前倒的。如果“投影在凸包内”是站稳的判据，那所有人走路时都不稳。

所以必须换一个能同时描述“站着”和“正在往前倒”的量。

## 零力矩点：地面推你的那个力的作用点

脚踩在地上，地面给脚一个反作用力（法向力加摩擦力）和一个反力矩。**零力矩点（Zero Moment Point，ZMP）定义为：把这个反力系向地面某一点简化，使得该点上的倾覆力矩为零的那个点。**

直觉版本：**地面“推你”的合力，等效作用在脚底的哪个位置。**

```text
设重心位置 (x, z)，速度 ẍ、z̈，质量 m，重力 g
水平/垂直方向的合力产生惯性力，ZMP 位置 p 满足：

p_x = x − z · ẍ / (z̈ + g)
```

（这是线性倒立摆模型下的一阶式子 [行]；完整版要用角动量方程，本书只需要这一阶，因为它给出的物理已经够用。）

看这个式子在说什么。它把“重心在哪（x）”和“重心怎么加速（ẍ）”合成了一个点：

- **站着不动**：ẍ = 0 ⇒ p = x。ZMP 就是重心投影。
- **往前加速**：ẍ > 0 ⇒ 减掉的是一项**正数** ⇒ p 往后移。**想让身体往前加速，ZMP（≈接触点）必须落在重心投影的后面**：只有地面支持力作用在重心之后，重力绕接触点的力矩才把身体往前带。地面只能推、不能拉，这是唯一可行的方向。
- **往前但要刹车**：ẍ < 0 ⇒ 减去的是负数 ⇒ p 往前移，ZMP 跑到重心投影**前面**，用反过来的力矩把前倾拽住。
- **自由落体**（z̈ = −g）：分母为零，p 无定义——**这时候地面已经不推你了，“稳不稳”这个问题暂时不存在。**

最后一行有个立刻可用的推论：**跳起来的那段时间里没有 ZMP 概念可言。** 所以人形机器人在腾空相不需要维持平衡，它只需要在落地前把姿态摆对。这是“走路比跳简单”和“跳比连续小步跑容易控制”这两件事的共同来源。

## 判据：ZMP 在支撑多边形内就不翻

现在把上一章的几何接上：

```text
ZMP 落在支撑多边形内  ⇒  地面反力不需要“拉”地面 ⇒ 不翻
ZMP 落到多边形外       ⇒  需要一个拉力才能维持，而地面不给拉力 ⇒ 开始转动 ⇒ 翻
```

第二行的因果值得说细一点。ZMP 跑出凸包意味着要维持这个运动状态，地面必须提供一个“往回拽”的法向力——但脚和地面之间只能压不能拉（除非有磁吸或绑带）。所以真实的物理会**放弃**那个运动状态：脚的前缘离地，机体开始绕脚边缘转动。

于是“站稳”这件事第一次有了一个可计算的标量：**ZMP 到支撑多边形边界的最短距离。** 这个距离叫稳定裕度。工程上它比“在不在里面”有用得多，因为：

- 在里面的一个点，离边界 2 mm，实际上等于已经不稳（模型误差、地面不平、脚底有泥都会吃掉那 2 mm）；
- 控制器需要一个**连续**的目标函数，“在/不在”是二值的，没法优化。

## 但 ZMP 有三个前提，每一个都会破

这是本章真正想给的东西：一个判据的价值，一半在于知道它什么时候不成立。

**前提一：脚是一个刚性的、完全贴合地面的面。**

真实情况：G1 的脚是带圆弧的（官方 MJCF 里踝关节下方是脚掌几何），地面是瓷砖、地毯、或者有一粒沙子。一旦实际接触退化成一条线甚至一个点，“支撑多边形”这个概念本身就塌了——而 ZMP 的判据还在按整个脚掌面积算。

**后果**：在不平地面上，ZMP 判据会给出一个乐观的稳定裕度。

**前提二：机体是刚体。**

线性倒立摆模型把整个机器人当成一个质量集中在重心、下面接一根无质量杆的摆。而第 1 部刚讲完：一台人形是 23 个有齿隙（齿隙 = 输入端转了一小段而输出端不动的那段空程，第 14 章）、有弹性、有模态频率的关节串起来的。

**后果**：躯干摆动、手臂甩动、连杆弹性变形，都会让真实重心与模型重心不一致。这个偏差在第 22 章会变成 sim2real 的主要来源之一。

**前提三：接触力只能压不能拉，而且摩擦锥有限。**

判据只检查了“不拉”，没检查“不滑”。摩擦锥约束是另一个独立的限制：

```text
|F_切向| ≤ μ · F_法向
```

一个在冰面上做同样动作的机器人，ZMP 全程漂亮，但会滑倒。**ZMP 是抗倾覆判据，不是抗滑判据。** 两者必须同时检查。

（μ 的取值宇树从未公布 [未]；这也不是厂商该公布的数——它取决于地面。但它必须出现在控制器的约束里。）

## 捕获点：把“该迈哪一步”变成一个可解的方程

ZMP 判的是“现在这一瞬间会不会翻”。但走路的核心问题是**下一步把脚放哪**。捕获点（Capture Point）给了一个干净的答案：

> **如果我现在什么都不做，只让重心按当前的状态继续倒下去，那么我必须把脚放到哪个位置，才能在放下去的那一刻恰好停下来。**

对线性倒立摆，这个点有闭式解：

```text
x_cap = x + ẋ / ω₀        其中 ω₀ = √(g / (z − z_foot))

而 √(g/l) 正是第 16 章那个 τ 的倒数。
```

**这条式子值得停三秒。** 它说：捕获点的位置偏移 = 当前速度 × 倒立摆时间常数。也就是说：

- 速度越快，你必须迈得越远——不是“大概更远”，是**严格线性**地更远；
- 腿越长（ω₀ 越小），同样的速度需要迈得越远；
- 如果你迈不到那个点，你**不可能**停下来，只能继续跑。

（最后一条就是“被推了一下之后为什么会跑两步”的完整解释：不是算法反应慢，是那一瞬间物理上只有“跑”这一个解。）

代一个数：G1 髋高 ≈ 0.66 m ⇒ ω₀ = √(9.80665/0.66) = 3.85 rad/s，τ = 1/ω₀ = 0.26 s。

```text
重心水平速度 0.3 m/s ⇒ 捕获点比当前投影超前 0.3 × 0.26 = 78 mm
重心水平速度 0.6 m/s ⇒ 超前 156 mm
```

（`foc_check.py pendulum()` 给 τ，这一步是 [算]。）

**78 mm 与 156 mm 这两个数，就是“这台机器一步该迈多远”的下界。** 一步迈不到 78 mm，0.3 m/s 的速度就停不下来。这也解释了为什么小个子人形的步幅天然小、步频天然高——它的 τ 更短。

## 于是有了两套流派

现在可以解释一件行业现象：为什么宇树公开的运控工序是强化学习（第 21 章），而不是 ZMP + MPC。

| | ZMP / MPC 路线 | 强化学习路线 |
|---|---|---|
| 判据 | 显式：ZMP 在凸包内、摩擦锥内 | 隐式：奖励函数里“不倒”给分 |
| 需要精确模型 | 是（质量、惯量、接触） | 否（训练时随机化这些） |
| 处理不平地面 | 需要额外的接触模式规划 | 策略在随机地形上训过 |
| 可证明安全 | 原则上可以（约束是显式的） | 原则上不行 |
| 算力 | 一次 QP 求解，毫秒级 | 一次前向推理，微秒到毫秒级 |
| 出问题能不能解释 | 能（看约束与求解器状态） | 很难 |

**关键分歧不在“谁更稳”，在“你愿不愿意为可解释性付建模成本”。** 人形的接触模式（几只脚着地、躯干会不会撞、手里端着东西）组合起来是指数级的，显式建模这条路在工程上贵得离谱。所以 2016 年之后，足式运控的主流从“模型 + 优化”整体转向了“仿真 + 学习”。

但请注意：**ZMP 与捕获点没有消失，它们换了位置。** 它们现在是：

1. 强化学习**奖励函数**里的项（惩罚 ZMP 出界、奖励落脚接近捕获点）；
2. 仿真里生成参考轨迹的工具；
3. 工程师**判断策略为什么摔**的诊断量。

也就是说：**学会用 RL 之前，必须先懂 ZMP，否则你连奖励函数都写不出来。** 这一章就是为那个准备的。

## 类比，以及它在哪儿破

类比：ZMP 是地面推你的合力的“着力点”，就像你推一扇门，力的作用点决定门怎么转。捕获点是“你得把脚垫到哪，这根正在倒的扫帚才停”。

**这个类比在哪里破**：扫帚倒向你手掌时，你的手是**被动**接住的；而人形的脚是**主动**迈出去的，而“迈”这个动作本身要花时间（摆动相 200 毫秒量级，第 16 章）。所以捕获点判据有一个隐含前提：**从现在到脚落地的那段时间里，你的重心状态不能再被扰动改变。** 一旦有人在半路又推你一把，你算好的那个捕获点当场作废，必须重算——而重算需要新的 200 ms。

**这就是“被连续推会摔”的物理原因**：不是控制器不够快，是腿这个执行器天生就慢。而腿慢的原因在重力——τ = √(l/g) 里那个 g 你换不掉。

---

**一个可检验的说法**：站稳的可计算判据是 ZMP（地面反力系的等效作用点）落在支撑多边形内，其稳定裕度是 ZMP 到凸包边界的最短距离；ZMP 判据成立需要三个前提（脚为完全贴合的刚性面、机体为刚体、接触满足摩擦锥），三者在不平地面、弹性机身、低摩擦地面上会依次失效；捕获点 x_cap = x + ẋ/ω₀ 给出“要停下来脚必须放到哪”，其偏移量等于速度乘以倒立摆时间常数（G1 为 0.26 s，故 0.3 m/s 需超前 78 mm）。

**证据等级**：ZMP 定义与线性倒立摆公式、摩擦锥约束、捕获点闭式解，全部是足式机器人控制的标准内容 [行]（可查 Raibert 与 Pratt 的原始文献）；τ = 0.26 s、ω₀ = 3.85 rad/s、78/156 mm 是 [算]；髋高 0.66 m 是本书按官方身高与腿长估读 [算]，**不是官方值**；“宇树用 RL 而非显式 ZMP/MPC”是从其公开仓库（unitree_rl_gym / rl_lab）推出的 [厂]，但**宇树从未公布整机在线控制律**，G1/H1 出厂固件里跑的到底是什么，是 [未]；μ 与接触几何参数全部 [未]。

**可核对清单**：

- [ ] 自己代一次 ω₀ = √(g/0.66) 与 0.3 × 0.26，确认 3.85 rad/s 与 78 mm
- [ ] 用 p_x = x − z·ẍ/(z̈+g) 推一遍“腾空相分母为零”，确认那时 ZMP 无定义
- [ ] 找一段人形被推的视频，慢放数一下从被推到另一只脚落地过了几毫秒，和 200 ms 比
- [ ] 想清楚为什么“稳定裕度”必须是连续量而不是“在/不在”——这个问题的答案是所有 MPC 代价函数的写法
