## 看见之后：把碎片拼成"我在哪"

上面所有传感器给的都是**相对量**：这一帧比上一帧动了多少、这一圈回波有多远、这一瞬间角速度是几。
可真正要用起来的是一个绝对的东西——"我的躯干现在在世界的哪个位姿"。这中间差着一层，
行业里叫**状态估计**（把一堆带噪声的相对测量拼成一个可用的当前状态），再往上叫**定位**
（长期地知道自己在哪，通常还要顺手把地图建出来，即 SLAM）。

**第一个追问：两个都不准的东西，凭什么合起来会更准？**

因为它们的**不准是不一样的**。设陀螺给的角度不确定度 σ₁ = 0.1°，加速度计算出的倾角 σ₂ = 0.5°。
按精度加权（权重取方差倒数）合并，合成不确定度是

```
σ = 1 / √(1/σ₁² + 1/σ₂²) = 1 / √(100 + 4) ≈ 0.098°
```

看这个数：**0.098°，只比最好的那一路（0.1°）好了一点点。**
所以"融合能救命"是外行话。融合真正买到的不是精度，是**可观测性**
（某个量能不能从测量里唯一地反推出来）：陀螺测得出角速度，但**测不出绕重力轴转了多少**——
那一路怎么积分都是"看起来对"；而加速度计在静止时能看出重力方向，于是它管住了俯仰与横滚。
少一路，某些方向就永远定不下来，多好的滤波器也没用。

**第二个追问：这个"加权"具体是怎么一直做下去的？**

最主流的写法是扩展卡尔曼滤波（EKF，一种把非线性系统线性化后反复求均值与方差的递推估计器），
它只有两步，循环执行：

```
预测：用运动学把状态往前推一步，方差变大（因为过程有噪声）
更新：拿一次实测做加权平均，方差变小
```

因子图（把每一次测量当成一个要最小化的约束项，攒起来一起解）是同一件事的另一种算法形态，
区别是它**不丢历史**，所以能用后来的测量回头修正很久以前那次估计。
这两条路线本书都只讲机制：宇树**未公布**它的状态估计实现，也**未公布**是否用 EKF 或因子图 [未]。
它的 DDS 话题里给的是原料（quaternion / gyro / accel / rpy），不是成品。本节全部按 [行] 处理。

**第三个追问：为什么必须一直更新，攒一会儿再算不行吗？**

因为误差是**积分**出来的。陀螺那条：1 °/s 的零偏（静止时也有的固定读数偏差），
100 秒后就是一百度的姿态差。位置更狠，因为位置是加速度**积两次分**：

```
位置误差 ≈ ½ · b · t²        b = 加速度零偏
b = 0.01 m/s²、t = 10 s  ⇒  ½ × 0.01 × 100 = 0.5 m
```

一台人形在原地不动，只要那 0.01 m/s² 的偏差不被别的东西拉住，十秒后就"走出半米"。
这不是算法笨，是数学：二次方不等人。

**那靠腿自己数步数行不行？** 这就是腿式里程计：用 23 个关节的编码器读数反推足端相对躯干的位置，
再假设"着地的那只脚不打滑"，就能从脚推回躯干。它便宜、高频、不用外部设施，
但误差随步数**随机游走**（每步一个方向随机的错，累加起来按步数的平方根增长），
而且打滑这件事**在它自己的模型里不可观测**——它把滑掉的那几厘米当成真的走了。

**唯一能把误差清零的是"认出老地方"**：视觉回环（在传感器序列里发现"这一帧和很久前那一帧是同一个地方"，
于是把中间累积的漂移一次性拉回去）。这也是为什么定位系统一定要"走过才知道、知道要回头改"——
先要动才能测，测完才能修正，而修正又会改变你对之前轨迹的看法。这个耦合是这一层真正的难点，
不是算力问题。

**边界：融合救不了什么。** 两路传感器如果被同一个物理量一起带偏（同一条温度曲线把陀螺零偏和
加速度计标度因数同时拖走），加权平均毫无办法——它只能压住不相关的噪声。
另一条边界是模型：把打滑当成纯滚动，再精确的滤波器也会收敛到一个错误的答案。
