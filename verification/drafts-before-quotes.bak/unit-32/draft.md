# 宇树的 UnifoLM：一个开源动作，和它的许可条款

> 状态：初稿 v1（2026-10-08）。本章讲一家公司怎么把“大脑”放到公共领域，以及条款里藏着什么。

## 先把三个模型和它们的许可证分清楚

宇树在模型侧公开的是一族叫 **UnifoLM** 的东西。名字相近、时间不同、**许可条款不同**，而这三件事混在一起时最容易出错：

```text
UnifoLM-WMA-0     世界模型-动作（World Model + Action）
                 2025-09 发布；许可：CC BY-NC-SA        [厂]
UnifoLM-VLA-0     视觉-语言-动作；**仓库里没有 LICENSE 文件**（本书逐文件核对）[厂]
UnifoLM-WLA-1.0   6B 参数全身协调基座；官方称约 2,500 小时真机数据、
                 单模型 64 任务；2026-09-28 放出 Base 权重
                 许可：Apache-2.0                      [厂]
```

（以上参数、数据时长、任务数、发布日期均为**厂商在自家仓库 README 里的自陈**，本书如实转述并标注；第三方独立复现结果有限 [推]。）

外加一个数据侧的动作：Hugging Face 上约 **200 个 LeRobot 格式数据集** [厂]，以及 `unitree_IL_lerobot` 训练脚本（其 v0.3 起支持 **GR00T 与 π0.5** 策略 [厂]）。

**这一族东西合起来说明了一件事**：宇树没有自研一个封闭的“机器人 OS + 独家大脑”，而是把自己的机器接进**别人定义的标准**里——数据用 LeRobot 格式、策略支持 GR00T 与 π0.5、训练用 Isaac Lab、通信走 DDS（第 28 章）。

这个选择值得单独评一句，因为它和智元（自研 AimRT / Link-U OS）、银河通用（自带 GalbotSDK）的方向**正好相反**。

## 为什么“接标准”是理性的

一家卖本体的公司，它的价值主张是“我这台机器便宜、可靠、能量产”。而大脑的价值主张是“我的模型最强”。**这是两种不同的生意，而它们互相不需要对方的核心资产。**

所以宇树的理性选择是：**让别人的大脑能轻松装到我的机器上。** 具体做法就是把自己这边全部标准化：

```text
数据格式 → LeRobot（Hugging Face 生态的事实标准）
策略接口 → 支持 GR00T / π0.5（学界与工业界的现成权重）
训练环境 → Isaac Lab + 官方 MJCF/URDF（仿真里能直接跑）
通信     → DDS 主题 + 开源 SDK（不要求你装 ROS）
```

**这四条合起来的效果是：一个博士生可以在两周内，用宇树的机器、NVIDIA 的模型、Hugging Face 的数据格式，做出一篇论文。** 而这批论文与开源复现，就是宇树最便宜的营销。

**那这条链又靠什么撑住？** 靠一件事：这四层里没有一层是宇树定义的。数据格式是 Hugging Face 定的，策略权重是 NVIDIA 与 Physical Intelligence 定的，训练环境是 NVIDIA 定的，只有“机器能被这些标准接进来”是宇树做的。**所以它买到的东西叫装机量，代价是它的模型能力永远排在别人的路线图后面**——第 33 章会看到更硬的一版：数据分布由买它机器的人决定，不由它决定。

反过来看它的代价：**它放弃了“独家大脑”这个叙事。** 所以在“具身智能”的融资故事里，宇树讲不出“我们的模型别人没有”——它只能讲“我们的机器卖得最多、数据回流最快”。

（第 03 章那条募资分配正好印证这个自我认知：42 亿里 20.22 亿投具身模型。**它把一半的钱押在了自己不擅长的那件事上。** 而 WLA 用 Apache-2.0 开源，说明它的策略是“追平并接入”，不是“独家领先”。）

## 许可证不是法律细节，是产品参数

这一节是本章对读者最实用的部分。**CC BY-NC-SA 与 Apache-2.0 的差别，会直接决定你能拿这个模型做什么。**

| 条款 | 能商用吗 | 能闭源衍生品吗 | 要署名吗 | 要同许可分享吗 |
|---|---|---|---|---|
| **Apache-2.0** | 能 | 能 | 要（保留 NOTICE） | 不用 |
| **CC BY-NC-SA** | **不能（NC = 非商业）** | 不能 | 要 | 要（SA = 相同方式共享） |

所以：

```text
UnifoLM-WMA-0（CC BY-NC-SA）→ 你可以读、可以学、可以发论文；
                              你不可以拿它做产品或任何商业验证
UnifoLM-WLA-1.0（Apache-2.0）→ 你可以商用、可以闭源集成、可以改
```

**为什么这恰恰是一条产品策略，而不是法务疏忽？** 因为它是分档的：把“研究用”的东西放 NC（保护生态、要求分享），把“要别人真的装到机器上跑”的东西放 Apache（消除采用摩擦）。

**而这件事在中文技术圈几乎没人看。** 大家看 README 第一行的参数，不看 LICENSE。于是发生的情形是：一家公司拿 WMA-0 做了个 demo 去见客户——**这已经踩了 NC。**

**而本书逐文件核对时，抓到一处真正的许可冲突——两份都是官方文件：**

```text
unifolm-world-model-action：
   LICENSE 文件本体          = CC BY-NC-SA 4.0（非商业）
   pyproject.toml 的 license 字段 = BSD-3-Clause（可商用）
```

（[厂]。）**同一仓库、两份官方文件、结论相反。** 而 `unifolm-wla` 的 LICENSE 文件确实存在且是 Apache-2.0，另附 NOTICE 与 THIRD_PARTY_LICENSES.md——**这一项它做得比多数公司好。**

**本书的处理方式**：以 **LICENSE 文件本体**为准（也就是更严格的那一份），并把冲突如实列出。**理由不是法律判断，是风险不对称**——按宽松那份用，错了要承担侵权后果；按严格那份用，错了只是少用一个工具。

顺带两条同类的「官方文件互相不一致」，本书按同一原则处理 [厂]：

- `unitree_rl_lab` 的许可文件名是 **`LICENCE`（英式拼写）**，不是 `LICENSE`。**自动化许可扫描工具会漏掉它**，于是显示「无许可」。这是一个纯粹由拼写造成的法律状态误判。
- `unitree_rl_lab` 的版本号在三处不同：`pyproject.toml` 写 0.2.1、`extension.toml` 写 0.1.0、`CHANGELOG.rst` 最新条目 0.2.1（2025-07-17）。**你无法从仓库本身确定自己在用哪个版本。**

（`research/unitree-landscape.md` 另登记过宇树有 10 个仓库没有许可文件、其中一个「有 badge 无文件」。**「仓库里没写许可」在法律上意味着默认保留所有权利**，不是「随便用」。这一条对任何开源项目都成立，不只是宇树。）

## NC 拦住的到底是哪一步：把条款拆成动作

上一节那张表只回答“能不能”。工程师真正要的是“我做的这一步算不算”。把四个常见动作摊开判一遍（**本节是条款解读，不构成法律意见** [行]）：

```text
① 读代码、跑推理、写论文        → 可以（BY 要求署名并标注改动）
② 在公司内部拿它做可行性验证    → 不行，这一条最反直觉
③ 用你自己的数据微调它的权重    → 产物仍是改编材料，NC 与 SA 一起跟着走
④ 把微调后的权重闭源或发出去    → SA 要求以相同许可分发，闭源这条路做不到
```

**为什么②也不行？** 因为 NC 判的是**用途指向**，不是“你有没有卖这个文件”。非商业条款的通行理解是“不得主要用于商业优势或金钱报酬”；你跑一次可行性验证，目的是决定要不要把资金投进某个方案——**这就是商业优势。** “只是内部测试、没有分发”这句话救不了你：你分发的是决策依据。

**为什么③也不行？** 这是最容易误判的一格。CC BY-NC-SA 4.0 里，微调产物属于**改编材料（Adapted Material）**：ShareAlike 要求它沿用同一许可，NonCommercial 也跟着走。**换了数据、换了动作头都没用——只要权重是从那份 NC 起点来的，它还是 NC。起点决定终点。**

**于是这条约束有一个非常具体的工程后果。** 想拿它做商用验证的人，不能走“下载权重 → 微调 → 上线”，只能走“读它的代码与结构 → 用可商用的数据与骨干从零训练”。前者是几天的活，后者要把第 33 章那笔账整个付一遍。**许可条款在这里不是法务问题，是预算问题。** 而“等它以后改成 Apache”也不成立：一份已经放出的 NC 权重不会因为你等就变松，而本书无法核实 HF 上某个权重文件对应哪一份许可声明 [未]。

**Apache-2.0 那一边为什么没有这个坑？** 它授予商用、修改、闭源再分发，义务只有两项：保留 LICENSE 与 NOTICE 的版权声明，改动过的文件要注明改动。它还多带一条多数工程师忽略的东西：**专利授权**——贡献者授予你专利许可，你若对这些贡献者提起专利诉讼，该许可终止。在机器人这种专利密集的领域，这一条有实际价值，而 MIT 与 CC 都没有 [行]。

## 为什么 WLA 用 Apache、WMA 用 NC：上游替它做了决定

一家卖本体的公司，为什么要在同一族模型上用两种相反的许可？这一档差别不像市场部的决定，更像被依赖链逼出来的。`unifolm-wla` 仓库里有一份 **THIRD_PARTY_LICENSES.md**，逐条登记第三方来源 [厂]：

```text
starVLA      = MIT
Qwen-Image   = Apache-2.0
OpenVLA      = MIT（overwatch.py 自述来自 OpenVLA）
```

本章前面说过“许可证会传染，而且传染方向是收紧”。**把这句话反过来用，就解释了 WLA 的选择**：它的权重里蒸进了 Apache-2.0 的骨干与 MIT 的训练框架，而通行理解是——附加条款不得与上游条款冲突，所以把融了这些上游的产物整体声明成“非商业”，通常做不到 [行]。**想产品化就只能 Apache。这不是姿态，是链条推出来的。**

对照着看 WMA-0 那一侧：它的依赖里有一串可商用的库（`torch`、`diffusers`、`open-clip-torch`、`kornia` 等 [厂]），但它自己的 LICENSE 文件写的是 CC BY-NC-SA。**同一家公司、同一族模型、两份相反的策略**，而本书能核实的是结果，不是动机——动机那一句是厂商没公布的 [未]。

**代价要一起说。** 把研究侧锁进 NC，挡住的第一个人是竞争对手，第二个人是**你自己想产品化的团队**；而把基座放 Apache，等于把“别人在你机器上做出什么”这件事交出去——第 33 章会看到，这条路线买到的东西叫**生态装机量**，付出的东西叫**数据分布由别人决定**。

## 一个可以带走的检查动作

以后你要用任何一个开源模型/数据集/仿真资产，做四步，每步五分钟：

**第一步，打开 LICENSE 文件本体，不要看 README 的 badge。** badge 是作者贴的图片，LICENSE 才是条款。两者不一致时以文件为准。

**第二步，找三个词**：`commercial`（商用）、`derivative`（衍生）、`share-alike` / `same license`（相同方式共享）。这三个词决定 90% 的使用场景。

**第三步，检查数据集的许可是否与模型分开。** 这是最容易漏的一项：**模型 Apache-2.0，不代表用它训练的数据集可以商用。** LeRobot 格式的数据集各自带各自的 license，宇树 HF 上约 200 个并非同一份许可。你要用数据，得逐个查。

本书替你把这一项查了一遍（分页接口逐条抓，2026-10-08 [厂]）：

```text
总数        = 200（skip=199 返回 1 条、skip=200 返回 0 条）
按机型      G1 = 191 个、Z1 = 6 个、资产类 = 3 个
H1 / H2 / R1 = 0 个
许可元数据  标 apache-2.0 的 = 64 个
            没有任何 license 字段的 = 136 个（含 44 个 G1_WBT 全身遥操集）
```

**这三行里有两条是判据。** 一，**「宇树开源了人形全身数据可供任意使用」这句话不成立**：操作数据全部来自 G1 与 Z1，最重的机型（H1/H2/R1）一集都没有，而机型之间的质量、尺寸、扭矩档位全不一样（第 33 章）。二，**136 个没有许可元数据**——「公开可下载」不等于「可商用」，而 `unitree_rl_lab` 的 README 让你去 clone 的那个 `unitree_model` 资产集恰好在这 136 个里 [厂]：**一条官方推荐的训练流程，它的依赖资产法律状态是空的。**

**第四步，检查它引用的第三方。** 一个“Apache-2.0”的仓库可能依赖一个 GPL 的库、一个 CC-BY-NC 的预训练权重、和一个需要单独授权的商业仿真器。**许可证会传染，而且传染方向是收紧。**

（本书在 `bible/images.md` 里对图片做了同样的处理：OpenStax 与 MIT OCW 的素材带 NC 条款，因此**本书一张都不用**；官方产品图没有新闻资料包授权，也一张不用。这不是过度谨慎，是因为“这个图网上有”在法律上不是理由。）

## “6B / 2500 小时 / 64 任务”这三个数该怎么读

厂商自陈的三个数，逐个给判据。

**6B 参数**。含义在第 26 章：6B × 2 字节 = 12 GB 权重。这决定了它**跑不进 G1 EDU 那块 16 GB 的 Orin NX**（12 GB 权重 + KV + 激活 + 多路图像，16 GB 装不下），必须要么量化到 FP8/INT4、要么跑在 Thor 的 128 GB 上、要么在机外推理。**所以“6B”这个数真正的信息是：它需要 Thor 这一档硬件，或者一台外置 GPU。** 这是可以从参数直接推出来的部署结论，而宣传里不会告诉你。

**再往下追一层：节奏。** 权重必须整份从显存里搬一遍，所以单步下限 = 权重字节 ÷ 内存带宽（第 26 章那条，本书脚本 `foc_check.py` 里的 `llm_memory_time()` 就是这一行除法）：

```text
12 GB ÷ 100 GB/s = 120 ms 一步   ⇒   1 ÷ 0.12 = 8.3 Hz
6 GB ÷ 100 GB/s  = 60 ms 一步    ⇒   1 ÷ 0.06 = 16.7 Hz   （FP8 之后）
```

（[算]；100 GB/s 是第 26 章表里的那一档，**宇树未公布 PC2 模组的内存带宽，位宽是本书假设** [未]。）

**于是 6B 这一项能推出三条可核对的结论**：16 GB 的端侧模组装不下 FP16 权重；量化到 FP8 之后装得下，节奏仍在十几赫兹这个量级；而第 31 章那条要求（一块动作要覆盖一次推理，H·Δt ≥ T_infer）意味着 T_infer = 120 ms 时，块长至少要 H = 120 ÷ 20 = 6 步。**宇树没有公布 WLA 的推理频率、量化档位与部署方式** [未]，所以这三条是“如果按参数与带宽算会怎样”，不是对宇树实测的描述。

**约 2,500 小时真机数据**。对照第 33 章那张表：AgiBot World 是 2,976 小时、Generalist GEN-0 是 27 万小时。**2,500 小时在行业里属于“真实但不大”的量级。** 而它是真机数据（不是合成、不是人类视频），所以质量口径可能更高——但第 33 章说过，没有人有可信的换算比。

**单模型 64 任务**。这一项最容易被误读成“会 64 件事”。**它的正确读法是“在 64 个任务上评测过”**，而不是“64 个任务都成功”。**一个模型的任务数与它的成功率是两个完全独立的轴。** 而官方口径里，本书没有找到逐任务成功率 [未]。

**这三条判据（带宽→部署、时长→横向对比、任务数≠成功率）是本章想给的真正东西。** 它们不依赖宇树诚实与否，只依赖你会算。

## 类比，以及它在哪儿破

类比：开源模型像公开食谱。你可以照做、可以改、可以拿去开餐厅——除非食谱上写了“仅供家庭使用”。

**这个类比在哪里破**：食谱的“仅供家庭使用”是道德约束，没有强制力；而 CC BY-NC-SA 与 Apache-2.0 是**许可证条款**，在多数司法辖区有法律强制力，且违反的后果是侵权诉讼与产品下架。

更关键的破处：**食谱的成分是可见的，模型的“成分”（训练数据来自哪、用了谁的预训练权重、依赖哪些库）在模型卡里经常不完整。** 你拿到一个 Apache-2.0 的权重文件，可能里面蒸进了一个 NC 的视觉编码器。**这种“许可污染”在机器学习生态里是常态，而且无法从权重文件本身检查出来。**

所以本章最后给一条实操建议：**在你把任何开源模型放进产品之前，要求你的供应商/合作方给出一份“许可来源清单”，并且把它写进合同。** 这份清单在软件行业是标准交付物（SBOM），在机器人行业几乎还没有人做。

---

**一个可检验的说法**：宇树模型侧的公开动作是“接入标准而非自建封闭栈”——数据用 LeRobot 格式、训练支持 GR00T 与 π0.5、仿真用官方 MJCF/URDF、通信走裸 DDS；其 UnifoLM 一族内部许可不同（WMA-0 为 CC BY-NC-SA、WLA-1.0 为 Apache-2.0），而这个差别不是一句“能不能商用”，而是四个具体动作的许可：内部可行性验证算商业使用、微调产物作为改编材料继续带着 NC 与 SA、闭源再分发在 SA 下做不到，所以想商用验证的人只能重训而不能微调；WLA 选 Apache 还有一条可以核实的原因——它的 NOTICE 与 THIRD_PARTY_LICENSES.md 登记的上游是 MIT 与 Apache-2.0，附加更严的条件通常做不到；“6B”可以从带宽算出部署后果（12 GB ÷ 100 GB/s = 120 ms 一步、8.3 Hz，FP8 后 16.7 Hz），而 HF 那 200 个数据集里 H1/H2/R1 为零、136 个没有许可元数据。
